# Herdr App Groups & Spaces

[![CI](https://github.com/Jaxak/herdr-app-groups-spaces/actions/workflows/ci.yml/badge.svg)](https://github.com/Jaxak/herdr-app-groups-spaces/actions/workflows/ci.yml)

**Project Spaces** — независимая панель проектов для [Herdr](https://herdr.dev).
Объединяет существующие spaces в ручные группы и показывает терминалы их вкладок.

> **Pre-release:** опубликованных версий пока нет. Успешная загрузка проверена
> в Herdr 0.1.15 на Linux; другие версии и платформы пока не заявлены проверенными.
> Node-тесты и начальный native check не заменяют приёмку в живом окне.

## Возможности

- Создание, переименование и удаление групп прямо в панели.
- Перетаскивание проектов между группами, возврат в корень и изменение порядка.
- Создание проекта штатной командой Herdr, в том числе внутри группы.
- Терминалы всех вкладок проекта, иконки программ и переход к точной панели.
- Независимое сворачивание групп/терминалов и два сохраняемых переключателя.
- Компактная панель с линиями групп, двухбуквенными значками проектов и подсказками.
- Индивидуальные цвета групп и проектов: палитра темы, HEX-поле и сброс.
- Оформление групп: полоса 2 px, полная рамка или серая рамка с цветной левой границей.
- Активный проект с раскрытыми терминалами выделен в том же стиле, без заливки.
- Полные ID удалённых машин; группы могут объединять проекты разных машин.
- Штатное меню Herdr по правому клику или Shift+F10.

Данные сохраняются в Herdr shared state: `project-spaces.state`; временный запрос
создания проекта — `project-spaces.new`. Назначения недоступных проектов сохраняются.
Настройки локальны для Herdr home и не синхронизируются между компьютерами.

Подробное поведение и ручная приёмка: [docs/USAGE.md](docs/USAGE.md).
Проверенный объём и оставшиеся ограничения: [docs/VERIFICATION.md](docs/VERIFICATION.md).

## Требования и проверки

- Установленный Herdr с GPUI API и доступной командой `herdr-app`.
- Для разработки — Node.js 22+ и npm; зависимостей и сборки нет.

```sh
git clone https://github.com/Jaxak/herdr-app-groups-spaces.git
cd herdr-app-groups-spaces
npm run check
npm run check:herdr
```

`npm run check` проверяет синтаксис и запускает тесты с заменой Herdr API.
`npm run check:herdr` проверяет начальный рендер нативным движком и не устанавливает
мод. CI выполняет только первую команду; Herdr на GitHub runner не устанавливается.
`npm install` не требуется. Пакет помечен `private: true`: npm-публикация закрыта.

## Безопасная первая установка

Моды Herdr — доверенный код. Прочитайте исходники до установки. Наш мод не
использует сеть, exec или файловые API, но кнопка создания проекта запускает shell
через `space.new`; штатное меню Herdr может закрывать проекты и выполнять
worktree-действия. Не испытывайте эти действия на незаменимых рабочих сессиях.

Сначала сохраните резервную копию конфигурации и shared state **вне репозитория**.
Порядок резервирования и восстановления — в [CONTRIBUTING.md](CONTRIBUTING.md#работа-с-конфигурацией-herdr).

Команды ниже выполняются **в Bash из корня репозитория**. Herdr должен быть запущен.
Посмотрите имя текущего layout: оно понадобится для возврата.

```sh
herdr-app status
```

Следующий блок откажется перезаписывать существующий мод или layout. Клонирование
**сразу переключает окно** на копию layout `main`; проекты и терминалы не закрываются.

```bash
(
  set -eu
  herdr_home="${HERDR_APP_HOME:-$HOME/.config/herdr-app}"
  target="$herdr_home/mods/project-spaces"
  test -d "$herdr_home/mods"
  test ! -e "$target"
  test ! -L "$target"
  test ! -e "$herdr_home/layouts/project-workspace.json"
  test ! -L "$herdr_home/layouts/project-workspace.json"
  mkdir "$target"
  cp mods/project-spaces/*.js mods/project-spaces/*.svg \
    mods/project-spaces/mod.json mods/project-spaces/LICENSE-* \
    mods/project-spaces/THIRD-PARTY-NOTICES.md NOTICE "$target/"
  herdr-app check "$target"
  herdr-app do layout.clone '{"name":"main","as":"project-workspace"}'
)
```

В `<Herdr home>/layouts/project-workspace.json` (`$HERDR_APP_HOME` или
`~/.config/herdr-app`) найдите
блок с `"content": { "mod": "spaces" }` и замените **только** значение мода на
`"project-spaces"`. Остальные поля сохраните. Штатный layout `main` и мод
`spaces` не редактируйте. `place: "none"` не добавляет панель автоматически.

Если имя мода или layout занято, сначала выясните, кому принадлежит копия.
Не удаляйте её и не обходите защиту автоматической перезаписью.

После подключения:

```sh
herdr-app status
herdr-app shot /tmp/project-spaces.png
```

Проверьте отсутствие ошибок, снимок и сценарии из [ручной приёмки](docs/USAGE.md#ручная-приёмка).
Снимок может содержать пути, названия проектов и текст терминалов: не публикуйте его
без редактирования приватных данных.

## Обновление и откат

Обновляйте только свою установленную копию после сравнения и резервирования её
файлов. Сохраняйте все лицензии и notices вместе с модом. Сохранение исходников
вызывает hot reload; после обновления повторите native check и посмотрите status.
Автоматической миграции или очистки пользовательского shared state при установке нет.

Чтобы убрать панель, переключитесь на прежний layout из первого `status`.
Например, если это был `main`:

```sh
herdr-app do layout.switch '{"name":"main"}'
```

Это не удаляет группы или назначения. Для отката кода используйте резервную копию;
не заменяйте работающий `shared.json` вручную.

## Ограничения

- Привязка нового проекта к группе основана на наблюдении за новым активным space,
  а не на возвращаемом ID; параллельное внешнее создание может ошибиться.
- Порядок spaces меняется только внутри одной машины; автопрокрутки при drag нет.
- Несколько panes одной вкладки отображаются отдельными строками с одним именем.
- Нет поиска, правил автогруппировки, синхронизации настроек или layout terminal blocks.

Подробности и остальные ограничения: [использование](docs/USAGE.md).
