# Участие в разработке

Изменения небольшие и проверяемые: одна причина на PR, без форматирования
постороннего кода и без новых зависимостей ради нескольких строк.
Перед изменением поведения ознакомьтесь с [использованием](docs/USAGE.md)
и известными ограничениями. Старые планы — история решений, а не текущая спецификация.

## Локальные проверки

Нужны Node.js 22+ и npm. Никаких npm-зависимостей устанавливать не требуется.

```sh
npm run check
git diff --check
```

`check` выполняет `check:syntax` и `test`. Тесты используют Node VM modules,
заменяя только GPUI/Herdr API: это не нативные UI-тесты.

Если установлен Herdr:

```sh
npm run check:herdr
```

При изменении логики сначала воспроизведите ошибку или новое требование тестом,
увидьте ожидаемое падение, затем внесите минимальную правку и прогоните весь набор.
Проверяйте пустые данные, исчезнувшие цели, полные remote IDs и несколько view
поверх общего состояния. Изменения UI дополнительно требуют
[ручной приёмки](docs/USAGE.md#ручная-приёмка) затронутых сценариев.

В CI проверяются Node.js 22 и 24. Проверки на других версиях или платформах
пока не заявляются. CI не устанавливает Herdr, не видит ваш home и не доказывает
поведение нативного фокуса, перезапуска или удалённой машины.

## Работа с конфигурацией Herdr

- Разработка ведётся в репозитории. Установка в пользовательский Herdr home
  выполняется отдельно, с разрешения владельца окна.
- До первой установки сохраните копию своего layout, установленного мода (если он
  уже есть) и shared state вне git. Для согласованной копии файлов состояния
  закройте Herdr обычным способом самостоятельно; агент не должен останавливать
  приложение или core за вас.
- Штатные layout и моды не редактируются. Клонирование layout сразу переключает окно.
- Сравнивайте установленную копию перед обновлением; не перезаписывайте чужие правки.
- Для проверки используйте отдельные тестовые проекты. Команды создания/закрытия
  не выполняйте на рабочих сессиях ради теста.
- Восстанавливайте файловую резервную копию только при закрытом Herdr. Замена общего
  shared state затрагивает и другие моды: сначала сохраните текущую копию и оцените
  более поздние изменения. Для обычного отката достаточно вернуть предыдущий код
  или переключить layout; удалять shared state не требуется.
- Status и снимки проверяйте после установки/изменений. Перед отправкой снимка
  удалите приватные данные. Успешный hot reload — не замена полному тестированию.

## Pull request

1. Создайте ветку от актуальной main. Не переписывайте историю main.
2. Опишите причину, новое поведение и риски для сохранённых настроек/рабочих сессий.
3. Приложите результаты проверок; явно назовите непроверенные нативные сценарии.
4. Обновите README/docs при изменении поведения и CHANGELOG в разделе Unreleased.
5. Сохраните стороннюю атрибуцию. Присылайте только код, который вправе распространять.

Коммиты оформляются как `(тип): действие`, с русским глаголом в прошедшем времени:
`(feat): добавил проверку цели переноса`, `(fix): сохранил состояние группы`.
Оригинальные вклады принимаются под Apache-2.0; лицензии сторонних компонентов
сохраняют силу. Сам факт открытого PR не является разрешением устанавливать мод
или выполнять команды в пользовательском Herdr.

## Перед первой публичной публикацией

Это ручной checklist владельца репозитория, а не действия, уже выполненные CI:

- [ ] Проверены права на код и сторонние файлы; сохранены LICENSE/NOTICE и MIT/Apache notices.
- [ ] Просмотрены tracked файлы и вся история, включая секреты и приватные данные.
      .gitignore не удаляет уже закоммиченные файлы; найденные секреты нужно отозвать.
      Рабочий email авторов в этой истории разрешён владельцем.
- [ ] После отдельно разрешённого push выполнен реальный GitHub CI на main.
- [ ] В GitHub main выбрана default branch; настроен ruleset защиты от force-push
      и удаления, обязательные CI checks и PR. Обязательное стороннее review
      настраивается с учётом числа maintainer'ов, без невозможности принять собственный PR.
- [ ] При открытии репозитория включён Private vulnerability reporting;
      проверен маршрут из SECURITY.md. До включения канала подробности
      уязвимостей публично не принимаются.
- [ ] Проверены доступность Dependabot alerts и secret scanning/push protection,
      где они поддерживаются. Dependabot updates не заменяет эти настройки.
- [ ] Проверены pinned версии GitHub Actions и новые PR обновлений; автослияние не включалось.
- [ ] Пройдена ручная приёмка; записаны точные версии Herdr/ОС и непроверенные сценарии.
- [ ] В публичных иллюстрациях нет названий рабочих проектов, приватных путей и терминального вывода.

CODEOWNERS и workflow сами по себе не включают branch protection или private reporting.
Видимость репозитория изменяет только его владелец по отдельному решению.

## Выпуск версии

До первого выпуска CHANGELOG остаётся Unreleased, package.json — private
с технической версией 0.0.0; это не обещание опубликованного релиза.
Владелец отдельно выбирает версию, проверяет CI и ручную приёмку, переносит
пользовательские изменения в датированную запись CHANGELOG и разрешает tag/release.
В распространяемую папку мода входят JS, mod.json, SVG, THIRD-PARTY-NOTICES.md,
оба LICENSE-* и копия NOTICE из корня репозитория; generated SDK и локальная
конфигурация в неё не входят.
npm-публикация и автоматический выпуск артефактов не настроены.

Уязвимости обсуждайте по [SECURITY.md](SECURITY.md), не в публичном issue.
