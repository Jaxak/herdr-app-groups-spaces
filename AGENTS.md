# Работа с репозиторием

## Область и источники истины

- Код мода: `mods/project-spaces/main.js`; чистая модель: `model.js`;
  тесты: `tests/`. GPUI/Herdr imports существуют только в хосте, не в Node.
- При изменении UX сначала читай [docs/USAGE.md](docs/USAGE.md).
  `docs/plans/` — история согласований; старые планы не заменяют актуальный код
  и текущий запрос пользователя.
- При изменении Herdr API читай `AGENTS.md` и `*.d.ts` установленного Herdr home
  (`HERDR_APP_HOME` или `~/.config/herdr-app`). Сверяй поздние состояния:
  VM builder в тестах не проверяет все ограничения нативных элементов.

## Изменения и проверки

1. Проверь ветку, status и diff; сохрани посторонние изменения. Используй
   тематическую ветку; меняй `main` только по прямому указанию пользователя.
2. Для нетривиальной логики добавь регрессионный тест и подтверди RED → GREEN.
   Сохраняй полные remote IDs, перечитывай shared state в обработчиках и проверяй,
   что цель действия ещё существует.
3. Выполни `npm run check`, `git diff --check` и, если Herdr установлен,
   `npm run check:herdr`. В отчёте укажи пропущенные проверки.
4. Для изменений интерфейса проверь живое окно после отдельного разрешения:
   status без ошибок, снимок и затронутые сценарии ручной приёмки.
   Начальный native check не доказывает корректность фокуса, drag или перезапуска.

Сохраняй текущие слои и отсутствие npm-зависимостей. Новые зависимости,
файловые/сетевые API и exec требуют отдельного обоснования и согласования.
Retained input/focus создавай в init или обработчиках, а не в render;
используй cx текущего callback. Ограничение определения нового space по наблюдению
за списком описано в docs/USAGE.md: не расширяй его предположениями об ID.

## Границы безопасности

- Установка/обновление мода, переключение layout, создание/закрытие spaces и
  перезапуск Herdr — отдельные действия с разрешения владельца окна.
- Штатные моды и layout Herdr сохраняй неизменными; работай с личной копией.
  Persisted state меняй через shared/setShared, не редактированием shared.json.
- Не автоматизируй указатель или клавиатуру на рабочем дисплее. Для нативной
  автоматизации используй только изолированное окружение с разрешения владельца.
- Секреты, приватные снимки и Herdr home держи вне git. Рабочий email авторов
  в истории согласован; историю не переписывай.
- Push, release, tags, изменение видимости и правил GitHub требуют отдельного
  запроса. CI не должен получать секреты или устанавливать мод в живое окно.

## Лицензии и коммиты

Сохраняй LICENSE, NOTICE и файлы лицензий/атрибуции внутри мода.
При заимствованиях фиксируй источник, commit и изменения.
Производный main.js содержит Apache-2.0 и MIT части.

Сообщение коммита: `(тип): <действие по-русски глаголом в прошедшем времени>`.
Например: `(fix): сохранил назначения недоступных проектов`.

Для PR и выпуска следуй [CONTRIBUTING.md](CONTRIBUTING.md);
уязвимости направляй по [SECURITY.md](SECURITY.md).
