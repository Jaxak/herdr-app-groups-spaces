# Compact sidebar implementation plan

> **REQUIRED SUB-SKILL:** Use the executing-plans skill to implement this plan task-by-task.

**Goal:** Не сжимать полноразмерное дерево при сворачивании боковой панели и показывать полные названия в подсказках.

**Architecture:** Как в штатных Spaces, режим определяется по `layout()` — ширина узла `sidebar` меньше 160 px. Модель и shared state не меняются; это только представление существующего дерева.

**Tech Stack:** Herdr/GPUI, JavaScript, Node.js test runner; без новых зависимостей.

## Согласованное поведение

- Компактные группы: нейтральная левая линия вместо полной рамки.
- Компактные проекты: без вкладок и стрелок; активный проект отмечен акцентной левой линией, без заливки.
- Полные названия групп и проектов — в tooltip; доступные имена сохраняются.
- После расширения возвращаются рамки, прежняя подсветка и исходное раскрытие проектов.
- В узкой панели скрыты подписи, имя машины и служебные кнопки групп; общий плюс остаётся доступен.
- Черновик inline-редактора сохраняется, но сам редактор показывается только в широкой панели.

## Шаги

1. `tests/project-spaces.test.mjs`: добавить mock `layout()` и регрессии для ширин 44/76/159/160/268, отсутствующего sidebar, линий, tooltip, восстановления раскрытия и черновика. Подтвердить ожидаемое падение.
2. `mods/project-spaces/main.js`: добавить чтение ширины и компактные ветви существующих builders; центрировать кнопки шириной 32 px, убрать вложенные отступы. Обработчики выбора, контекстного меню и переноса сохранить.
3. `docs/USAGE.md`, `CHANGELOG.md`: описать режим и добавить пункты ручной приёмки.
4. Выполнить `npm run check`, `npm run check:herdr`, `git diff --check`; проверить diff на отсутствие изменений модели и установленного Herdr home.

Нативная геометрия и появление tooltip требуют проверки в живом окне после отдельно разрешённого обновления установленной копии. Mouse/keyboard automation, установка, перезапуск, push и release в задачу не входят.
