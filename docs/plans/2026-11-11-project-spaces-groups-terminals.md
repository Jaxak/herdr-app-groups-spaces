# Project Spaces: Groups and Terminals Implementation Plan

> **REQUIRED SUB-SKILL:** Use the executing-plans skill to implement this plan task-by-task.

**Goal:** добавить ручные группы проектов, вложенные терминалы и сохраняемые настройки без изменения штатных модов Herdr.

**Architecture:** `main.js` остаётся точкой входа панели, настроек и собственных overlay-экранов; чистые преобразования состояния и построение списка выносятся в небольшой `model.js`. Данные проектов и терминалов берутся из `spaces()` и `panes()`, пользовательские настройки — из одного namespaced-ключа `shared`.

**Tech Stack:** JavaScript, встроенные `gpui-kit`, `gpui-base`, `herdr`; Node.js 22+ и существующий VM-based test harness. Без новых зависимостей, сборки, опроса по таймеру и сетевых запросов.

---

## Согласованное поведение

1. Проект = существующий space. Группы создаются вручную, проект входит максимум в одну группу.
2. Управление прямо в панели через контекстные окна, не через список назначений в настройках и не перетаскиванием.
3. Меню панели создаёт группу; меню группы переименовывает или удаляет её; меню проекта назначает группу или переводит в «Без группы».
4. Удаление группы не закрывает проекты, вкладки или терминалы. Участники переходят в «Без группы».
5. В проекте видны терминалы с собственной панелью из всех его вкладок. Mod-панели, терминалы вне проекта и субагенты без панели не показываются.
6. Клик по терминалу выбирает его проект и вкладку, затем фокусирует именно его pane.
7. Два независимых переключателя: «Группировать проекты» и «Показывать терминалы». Оба изначально включены. Изменения применяются сразу, отдельного сохранения нет.
8. Выключение функции меняет отображение, не уничтожая группы, назначения, сворачивание или терминалы.
9. Группы и проекты сворачиваются; у проекта скрываются только терминалы. Изначально всё раскрыто. Состояние сохраняется между запусками.
10. При отключённой группировке проекты отображаются обычным списком.

## Минимальные детали реализации для утверждения вместе с планом

- Именованные группы идут в порядке создания, «Без группы» — последней, только если есть такие проекты. Внутри — исходный порядок `spaces()`. Пустая именованная группа видна, чтобы её можно было переименовать или удалить.
- В плоском режиме сохраняется исходный порядок `spaces()`, а не порядок групп.
- Группы могут содержать spaces разных машин. У удалённого проекта показывается имя машины; полные ID с префиксом машины нигде не обрезаются.
- Стрелка отдельно от названия сворачивает проект. Клик по названию только выбирает space. Сворачивание не переводит фокус и не закрывает объекты.
- У строки проекта и группы есть кнопка «…», открывающая то же меню, что правый клик. У заголовка панели — аналогичная кнопка для создания группы. Вложенные обработчики останавливают всплытие.
- Если терминалы отключены или у проекта их нет, стрелка проекта не нужна. Сохранённое сворачивание при этом остаётся.
- Название терминала: `pane.title`, иначе `pane.program?.name`, иначе адрес. Рядом имя/номер вкладки; порядок: вкладки space, затем панели соответствующей вкладки в порядке `panes()`.
- Меню создания/переименования открывает собственный диалог с `InputState` и кнопками «Сохранить»/«Отмена». Имя обрезается по краям; пустые и совпадающие после trim имена отклоняются с сообщением в диалоге. Сравнение регистрозависимое. Переименование в прежнее имя допустимо.
- Группы имеют стабильный ID, независимый от имени. Удалённые ID не переиспользуются. Переименование не теряет участников и состояние сворачивания.
- Отсутствующие/временно недоступные spaces скрываются, но их назначения и сворачивание автоматически не удаляются. Если Herdr вернёт тот же ID, настройки восстановятся; новый space с новым ID не наследует их по имени или папке.
- Настройки локальны для этого Herdr home, не синхронизируются с другими компьютерами через core.
- Существующие настройки панели и штатные файлы не трогаем. Установка в конфигурацию пользователя — отдельное подтверждаемое действие, не часть этого плана.

## Проверенные ограничения Herdr

Источники: `~/.config/herdr-app/AGENTS.md`, `herdr.d.ts`, объявления `InputState`/`Input` в `gpui-kit.d.ts`, штатные `mods/prompt/main.js`, `mods/menu/main.js` и `mods/spaces/main.js`.

- `spaces()` и `panes()` живые: меняются без polling; изменения `shared` перерисовывают все копии.
- Все panes доступны из `panes()`, связь с проектом — через `pane.tab` и `space.tabs[].id`; `pane.terminal === null` означает mod-панель.
- `run("space.select", {id})`, `run("tab.select", {id})`, `run("pane.focus", {pane})` используют строковые ID. Не полагаться на текущий фокус; не использовать `pane.focus {terminal}`, который может выбрать layout-блок вместо model pane.
- У popup/dialog есть `props().overlay`; меню закрывается перед открытием диалога или выполнением действия. Escape закрывает overlay, а Enter подтверждает действие ввода.
- Штатный `prompt` передаёт имя через app command и не поддерживает произвольный callback в props: для изменения своих групп нужен свой экран, а не выдуманная команда Herdr.
- `InputState.new` и focus handle создаются в `init`, не в `render`. Не сохранять обычный `cx` для позднего использования.
- `herdr-app check` не покрывает все поздние экраны и состояния. Нужны тесты обработчиков и ручная проверка в окне.

## Состояние

Один ключ: `project-spaces.state`. Начальный снимок:

```js
{
  settings: { groupProjects: true, showTerminals: true },
  groups: [], // { id: "g1", name: "Работа" }
  nextGroupId: 1,
  assignments: {}, // полный space.id -> group.id
  collapsedGroups: [], // group.id; "ungrouped" для «Без группы»
  collapsedProjects: [] // полные space.id
}
```

- Единственный доступ к persisted-состоянию — `shared`/`setShared`; `shared.json` вручную не читать и не писать.
- Отсутствующие поля дополняются значениями по умолчанию; явно записанный `false` не превращается в `true`. Проверить типы вложенных полей, строковых ID и имён, уникальность ID групп и корректность счётчика; неизвестные ссылки на группы считаются отсутствием назначения.
- Чтение/рендер не должны ничего сохранять или автоматически очищать назначения недоступных spaces.
- Каждый обработчик перед изменением перечитывает последнее состояние. Не сохранять snapshot, полученный при открытии настроек/меню: другая копия мода могла его изменить.
- В props overlay передаются только serializable ID/тип экрана, не callbacks, cx или снимок всего состояния.
- Перед применением действия ещё раз проверить существование space/group/pane. Устаревшее меню не должно применяться к текущему выбранному объекту вместо исходной цели.

- Проверить оба способа открытия меню, клавиатуру меню/диалога, ошибки имён и закрытие без сохранения.
- Проверить пустую группу, длинные имена, небольшой размер панели, светлую и тёмную темы, большое меню групп со скроллом.
- Проверить терминалы нескольких вкладок, удалённый проект при доступности, переключение между проектами и вкладками, zoomed tab и исчезнувший pane.
- Проверить все четыре сочетания двух переключателей, сворачивание, горячую перезагрузку и сохранение после перезапуска Herdr.
- Если разрешения на установку нет, не выполнять этот шаг; явно сообщить, что native UI, фокус и перезапуск не проверены.

**Step 4 — commit:** `(docs): описал группировку проектов и работу с терминалами`.

**Step 5 — отчёт:** перечислить коммиты, результаты проверок и точные непроверенные сценарии. После обратной связи использовать `finishing-a-development-branch`; не merge/push без выбранного пользователем действия.

## Не входит в этап

Drag-and-drop; группировка по папкам/репозиториям; несколько групп на проект; фоновые субагенты; отдельные окна и layout terminal blocks; создание/закрытие терминалов из панели; синхронизация настроек между машинами; поиск, сортировка, иконки/цвета групп, импорт/экспорт, виртуализация и произвольные горячие клавиши. Нет миграции или перезаписи штатной панели Spaces.
