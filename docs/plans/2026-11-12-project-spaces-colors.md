# Цвета групп и проектов: план реализации

**Цель:** один настраиваемый цвет на группу для её иконки/рамки/компактной линии;
отдельный цвет каждого проекта для папки в полном режиме и первых двух символов
имени в компактном. Буквы сохраняют регистр и рисуются без цветной плитки.

## Решение

- Палитра: шесть ANSI-цветов текущей темы и сброс к прежнему стандартному виду.
  ColorPicker в API хоста отсутствует; произвольный HEX-ввод не входит в эту итерацию.
- Хранение только в `project-spaces.state`: необязательный `group.color` и карта
  `projectColors` по полным space ID. Старое состояние без цветов остаётся рабочим.
  Не менять штатный ключ `space.colors`, не удалять цвета недоступных проектов.
- Валидировать значения палитры при чтении состояния и перед сохранением.
- Настройки: существующие переключатели плюс строки цветов групп/проектов;
  прокручиваемое содержимое и отдельная постоянно доступная кнопка закрытия.
- Цвета применяются сразу через shared state. Обработчики перечитывают состояние
  и не записывают цвет, если цель уже исчезла.

## Шаги и проверки

1. `tests/project-spaces.test.mjs`: RED для миграции старого состояния, независимости
   цветов, invalid/stale input, двух копий настроек, сохранения после reload,
   компактных букв и цветных иконок/границ в обоих режимах.
2. `mods/project-spaces/model.js`: палитра и нормализация цветов.
3. `mods/project-spaces/main.js`: выбор/сброс цвета, прокрутка настроек,
   двухсимвольные подписи и окрашивание существующих builders.
4. Обновить `docs/USAGE.md` и `CHANGELOG.md`; выполнить `npm run check`,
   `npm run check:herdr`, изолированные native probes для settings/full/compact
   и `git diff --check`.

Установленная копия, пользовательские layout/settings/shared.json, процессы,
Git history и remote не меняются. Визуальная приёмка новых настроек и цветов
в живом окне требует отдельного разрешения обновить установленный мод.
