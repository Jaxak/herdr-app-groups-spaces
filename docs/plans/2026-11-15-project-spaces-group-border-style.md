# Group Border Style Implementation Plan

> **REQUIRED SUB-SKILL:** Use the executing-plans skill to implement this plan task-by-task.

**Goal:** Добавить общую сохраняемую настройку оформления групп: вертикальная полоса 2 px по умолчанию или прежняя полная рамка.

**Architecture:** Сохранять `settings.groupBorderStyle` в существующем `project-spaces.state`, нормализовать в `readState`, выбирать оформление только у внешнего контейнера именованной группы. Настройки используют штатные `RadioGroup`/`Radio`; обработчик перечитывает shared state. Новых зависимостей, API файлов/сети и exec нет.

**Tech Stack:** JavaScript ES modules, GPUI/Herdr, node:test и существующий VM harness.

---

## Согласованные решения

- Одна настройка «Оформление групп» с вариантами «Вертикальная полоса» и «Полная рамка».
- При отсутствующем или некорректном выборе — полоса 2 px, в том числе для прежнего persisted state.
- Полоса слева, без закруглений, охватывает заголовок и видимых потомков. Прежние отступы, цвета и вложенность сохраняются; пустые и свёрнутые группы остаются оформленными.
- Цвет группы либо `theme().border`; цвет её значка не меняется.
- При ширине sidebar <160 px остаётся прежняя компактная полоса 1 px независимо от выбора.
- Полная рамка — прежние `border_1()` и `rounded(6)`.
- Временная акцентная рамка заголовка при переносе проекта остаётся.
- Настройка доступна при выключенной группировке, сохраняется и применяется сразу. Корневые проекты не получают оформления группы.
- Установка, изменение layout и проверка живого окна требуют отдельного разрешения и не входят в эту реализацию.

## Task 4: Согласованное дополнение — рамка с акцентом

**Goal:** Третий вариант «Рамка с акцентом» (`accent-frame`): нейтральная рамка темы 1 px, левая граница цвета группы 2 px, скругления 6 px. Значение по умолчанию и компактный режим прежние; без цвета группы используется нейтральная граница темы.

**Files:** `tests/project-spaces.test.mjs`, `mods/project-spaces/{main.js,model.js}`, `docs/USAGE.md`, `README.md`, `CHANGELOG.md`.

1. Исходные 100 тестов должны проходить. Расширить проверки нормализации, radio-вариантов, сохранения и компактного режима значением `accent-frame`; добавить проверки нейтрального контура и отдельной цветной стороны, пустых/свёрнутых групп, темы/HEX, отсутствия оформления в корне и сохранения drag-подсветки. Запустить `npm test`, подтвердить RED.
2. Нормализатор принимает `frame` и `accent-frame`, иначе возвращает `stripe`. В существующие radio-варианты добавить третий без изменения обработчика shared state.
3. GPUI предоставляет один `border_color` на элемент: в новом режиме контейнер имеет нейтральные `border_1().border_l(2).rounded(6)` и `relative()`, поверх левой стороны — абсолютный декоративный элемент с `border_l(2)`, цветом группы и теми же скруглениями. Отрицательные offsets равны толщине границ контейнера, чтобы контуры совпали. Декорация не участвует в flex-layout и не получает обработчиков/focus.
4. Обновить использование, README и Unreleased. Запустить `npm run check`, `git diff --check`, `npm run check:herdr`; отдельно материализовать новый режим и экран настроек во временной копии через native check.
5. Не обновлять установленный мод, не менять живое окно, shared state, layout или рабочие проекты; визуальная приёмка — отдельно с разрешения владельца.
