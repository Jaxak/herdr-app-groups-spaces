# Намерение: безопасная установка Project Spaces

## Статус и цель

Зафиксирована задача на будущее: автоматизировать корректную установку мода
`project-spaces` вместо ручного копирования файлов и редактирования layout.
Сейчас создаются только ветка и эта заметка; реализация и запуск установщика
не согласованы. Это намерение, а не утверждённый дизайн или план реализации.

## Предлагаемый подход

- Отдельный Node.js-скрипт без npm-зависимостей: Node уже требуется проекту.
- Учитывать `HERDR_APP_HOME`, по умолчанию использовать `~/.config/herdr-app`.
- По умолчанию показывать план без изменений; применять явно через `--apply`.
- Проверять подготовленную папку через `herdr-app check` до копирования
  в установленный мод. Начальная native-проверка не заменяет ручную приёмку.
- Копировать только файлы распространения: JS, SVG, `mod.json`, `LICENSE-*`,
  `THIRD-PARTY-NOTICES.md` и корневой `NOTICE`; не переносить generated SDK.
- Подключать мод в личном layout, сохраняя остальные поля и штатные файлы.
- При занятом имени не перезаписывать существующую копию автоматически.

## Границы безопасности

- Установка/обновление и переключение layout требуют отдельного разрешения
  владельца окна. `layout.clone` сразу переключает окно; это нужно учитывать
  при выборе способа подготовки личного layout.
- Запись в папку установленного мода вызывает hot reload.
- Не изменять shared state, штатные моды и layouts; не создавать и не закрывать
  spaces/терминалы, не перезапускать Herdr.
- Резервные копии и приватную конфигурацию хранить вне git. Согласованная копия
  файлов состояния требует закрытия Herdr владельцем по CONTRIBUTING.md.
- Проверять установщик на временном Herdr home; живое окно не использовать
  для автоматических тестов.

## Открытые решения

1. Только первая установка или также безопасное обновление? В изученном
   Herdr home `project-spaces` и несколько ссылающихся на него layouts уже есть.
2. При поддержке обновления: как выявлять локальные правки, резервировать
   изменяемые файлы и восстанавливаться после частичного сбоя.
3. Как выбирать личный layout и отдельно подтверждать его активацию.

## Ожидаемый объём будущей реализации

Скрипт, регрессионные тесты, инструкция в README и запись в CHANGELOG.
До реализации согласовать решения выше; для нетривиальной логики подтвердить
RED → GREEN, затем выполнить `npm run check`, `git diff --check` и, при наличии
Herdr, `npm run check:herdr`. Проверки живого окна — только с отдельного разрешения.
