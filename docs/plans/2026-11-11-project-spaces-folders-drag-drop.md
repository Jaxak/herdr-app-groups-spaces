# Project Spaces: кнопки папок и drag-and-drop Implementation Plan

> **REQUIRED SUB-SKILL:** Use the executing-plans skill to implement this plan task-by-task.

**Goal:** перенести кнопки Spaces и механику перетаскивания из `jankeesvw/herdr-space-folders` в существующий `project-spaces`, сохранив группы и вложенные терминалы.

**Architecture:** текущая модель `project-spaces.state` остаётся источником групп, назначений и сворачивания. Переносим UX и обработчики, а не git/polling/shell-код оригинала. Создание space использует `run("space.new", {machine})`; поскольку API возвращает null, краткоживущее shared-состояние `project-spaces.new` связывает единственный новый активный space нужной машины с группой. Перетаскивание хранит полные стабильные ID на экземпляре View; переносы проверяют актуальные данные перед изменением.

**Tech Stack:** JavaScript, GPUI/Herdr API, Node.js built-in test runner; без зависимостей.

## Согласованные границы

- Продолжаем в `feat/project-spaces-scaffold` (пользователь подтвердил).
- Меняем только область Spaces; существующие рамки групп, вложенные терминалы, настройки, меню и сохранённые данные остаются.
- Заголовок Spaces: высота 31 px, подпись 11,5 px в цвете dim, кнопки создания папки и проекта 26×26 px с нативными иконками. Управление и настройки доступны компактными кнопками.
- Кнопка folder-plus открывает существующий редактор группы: Cancel не создаёт папку. У именованных папок появляется собственный +; проект создаётся на машине текущего активного space, а без него — локально. Привязка к группе сохраняется по ID, даже если группа свернута. Повторный запрос во время ожидания не запускает ещё один space; тайм-аут 60 с. Неоднозначный результат не назначаем произвольной папке.
- Перенос проекта в папку меняет только назначение; разные машины допустимы. Перенос на другой проект также меняет порядок через space.move, но только внутри одной машины. В плоском режиме меняется только порядок, назначения остаются.
- Папки меняют порядок в state.groups. «Без группы» не перетаскивается. Пустые и свёрнутые папки принимают проекты.
- Используем press/move/release, подсветку назначения, линию вставки и полупрозрачный источник, отдельную нижнюю зону извлечения из папки. Обычный клик не начинает перенос; нажатия стрелок, меню, + и терминалов изолированы от drag. Escape и отпускание вне допустимой цели отменяют перенос. Устаревшие ID не затрагивают другой объект.
- Исходный мод Apache-2.0, дополнения MIT: сохранить обе лицензии и указать источник заимствования.
- Не переносим правила автогруппировки, цвета папок, git-метаданные, синхронизацию файлов, shell-команды и горячие клавиши. Установленную конфигурацию Herdr автоматически не меняем.
