# Security policy

## Поддерживаемая ветка

Исправления безопасности рассматриваются для текущей main.
Гарантированного срока ответа и отдельной службы поддержки нет.
Сейчас main содержит только инфраструктуру репозитория, без исполняемого мода.

## Сообщить об уязвимости

Используйте **Security → Report a vulnerability** в
[репозитории GitHub](https://github.com/Jaxak/herdr-app-groups-spaces).
Канал доступен только после включения владельцем Private vulnerability reporting.

Если кнопки нет, создайте issue лишь с просьбой включить приватный канал,
без технических деталей, секретов и действующих ключей.
Дождитесь безопасного способа связи. Не присылайте содержимое приватных файлов
через публичные issues, PR, логи или снимки.

В приватном отчёте укажите затронутый commit, окружение, воспроизведение и ущерб.
Публикацию эксплуатационных деталей согласуйте с владельцем.

## Модель доверия

CI выполняет код из pull request с минимальными правами и без секретов.
Это не основание доверять непроверенному PR-коду на личном компьютере.
Установка интеграций и доступ к пользовательским приложениям не выполняются
автоматически. При добавлении такой фичи её модель доверия и риски должны быть
описаны в том же PR.

Секрет, попавший в git, сначала отзовите: удаление файла не удаляет историю.
